# PetHelp — правила для агента

## 1. Продукт
PetHelp — помощник владельца собаки или кошки на время домашнего лечения: курс назначений в одном месте, чтобы не дать лекарство дважды и не пропустить приём.
Ключевой сценарий: фото выписки → проверка плана человеком (без дозы и срока курс не запускается) → экран «Сегодня» → «Дал»; помощник видит «Уже дано в 9:04» и не может отметить повторно.
Подробности — в PRODUCT.md.

## 2. Стек
- Next.js 16 (App Router; dev/build с `--webpack`) — перед кодом читать `node_modules/next/dist/docs/` (см. AGENTS.md)
- React 19, TypeScript
- Tailwind 4, дизайн-токены в `app/globals.css` через `@theme`
- shadcn/ui (локальные компоненты в `components/ui/`, Radix)
- Supabase (`@supabase/supabase-js`), миграции в `supabase/migrations/`
- Vitest (`tests/unit`), Playwright (`tests/e2e`, свой сервер на порту 3100)
- Node 24

## 3. Запуск и проверка
```text
npm ci              # установка зависимостей
npm run dev         # локально, обычно http://localhost:3000
npm run typecheck   # tsc --noEmit
npm test            # Vitest
npm run build       # продакшен-сборка
npm run test:e2e    # Playwright (один раз: npx playwright install chromium)
```
В PowerShell при блокировке npm.ps1 — `npm.cmd`. CI (`.github/workflows/ci.yml`) гоняет те же проверки.

## 4. Цикл фичи
1. Спецификация: `docs/specs/<фича>.md` по `docs/specs/feature-template.md` (Что / Для кого / Сценарий / Дано-Когда-Тогда / Чего не делать).
2. План: раздел «Принятый план» — файлы, команды, проверки.
3. Жду подтверждения человека. Без него код не пишу.
4. Выполнение строго по плану; отклонения — сначала согласовать.
5. Проверка: запуск проверок из п. 3, результат дописывается в «Фактическая проверка» той же спецификации.

## 5. Коммиты
- Формат заголовка: `feat: …`, `fix: …`, `docs: …`; в теле — зачем сделано изменение.
- Коммиты делает только человек. Агент может предложить текст сообщения.

## 6. Ограничения агента (каждое проверяется по diff)
- Не ставить и не удалять пакеты без одобрения — `package.json` и `package-lock.json` без согласования не меняются.
- Не читать и не менять файлы `.env*`.
- Не менять схему базы без новой миграции в `supabase/migrations/`; существующие миграции не редактировать.
- Не выполнять `git commit`, `git push`, `git revert`, `git reset`.
- Не менять `.github/workflows/` без запроса.
- Не писать цвета, размеры шрифта и радиусы прямо в компонентах — только токены из `app/globals.css`.
- Отметки приёма лекарства не удаляются и не перезаписываются — только новая запись или пометка «отменено».
- Вызов API модели — только в серверном коде `app/api/`, никогда в клиентских компонентах (`"use client"`).
